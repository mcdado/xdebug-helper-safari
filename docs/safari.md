# Safari packaging

This fork targets macOS Safari as a Safari Web Extension source package. Safari does not load the raw Chrome/Firefox extension directory directly; it needs an Apple wrapper generated by Xcode tooling or by App Store Connect.

## Current local environment

This machine is using Command Line Tools:

```sh
xcode-select -p
# /Library/Developer/CommandLineTools
```

With that setup, the local Safari packaging tools are unavailable:

```sh
xcrun --find safari-web-extension-packager
xcrun --find safari-web-extension-converter
```

Both commands fail unless full Xcode is installed and selected. This repo therefore produces a Safari-ready WebExtension ZIP and leaves the Apple wrapper/package conversion to App Store Connect or a future full-Xcode setup.

## Build the Safari source ZIP

```sh
scripts/build-safari-source.sh
```

The script creates:

```text
build/safari/xdebug-helper-safari@<manifest-version>.zip
```

The ZIP contains the extension files from `src/` plus `LICENSE`, and is intended for Apple packaging.

## Package through App Store Connect

1. Build the Safari source ZIP.
2. In App Store Connect, use the Safari Web Extension Packager flow to upload the ZIP.
3. Let App Store Connect convert/package it for testing.
4. Use TestFlight for private testing.

Apple’s overview: https://developer.apple.com/safari/extensions/

## Optional full-Xcode path

If full Xcode is installed later, select it and run Apple’s local packager:

```sh
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
xcrun safari-web-extension-packager ./src \
    --project-location ./Safari \
    --app-name "Xdebug Helper Safari" \
    --bundle-identifier com.example.xdebug-helper-safari
```

Use a bundle identifier owned by your Apple Developer account if you plan to sign or distribute the wrapper.
